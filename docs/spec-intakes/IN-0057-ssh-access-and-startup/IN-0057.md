# Spec Intake: SSH access and startup

ID: IN-0057
Date: 2026-11-10
Type: existing-contract change and new capability
Lane: high-risk

## Source

The owner selected administrator SSH/SFTP access with other restrictions retained,
replacement of the application terminal engine, and a configurable saved SSH session
to connect at startup. The owner subsequently requested implementation and explicitly
changed the engine target from librio-vt to libghostty-vt on 2026-11-10.

## Requested Outcome

Owner continuation (2026-11-15): explicitly permit confirmed administrators to
create/save new Sessions (US-0258), retaining existing-session mutations, startup,
vault and other configuration restrictions. Use an independent locked append.

Owner continuation (2026-11-14): add New SSH to terminal right-click menus,
with Quick Connect and existing saved sessions in its submenu. Reuse existing
connection dialogs and token/security policy; do not change connection defaults.

Owner continuation (2026-11-14): require native OSC 52 clipboard support,
jump-host routes, port forwarding and terminal output logging. First amend
requirements; do not present the current native preflight rejections as the
final feature scope. Preserve existing security/defaults and isolated storage.
Each independently acceptable capability needs its own work packet and detailed
design before implementation. Agent forwarding is a distinct capability and is
not added implicitly by the port-forwarding request.

Also verify a discoverable right-click action to close only the clicked split
Space, without closing its sibling sessions or the whole terminal tab.

Allow explicit SSH/SFTP use in administrator windows; make one saved session the
optional startup connection; assess and migrate the engine without breaking SSH.

## Project Impact

Actions, workspace layout, session management, startup, persistence, and engine integration.
No plaintext credential storage, implicit retry, or host-key bypass is permitted.

## Architecture and Boundary Questions

- Runtime: app wires startup; session-ui owns saved-session selection and connection.
- Data: session-ui owns the startup session id in ssh_session.json.
- Security: administrator config remains read-only; automatic startup connects only in ordinary processes.
- External effects: startup connection uses the normal approval/authentication path once, never retries automatically.
- Compatibility: preserve the embeddable oneterm-vt crate and its external public API.
